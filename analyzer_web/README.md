# Portable Evidence Analyzer

Локальное read-only веб-приложение для коллекций `tools/portable.ps1` схемы 3.0.
Каждый непосредственный подкаталог корня коллекций, содержащий
`portable_collection.json`, индексируется как отдельный проект.

## Запуск

### Jump Lists и профиль пользователя

Сборщик сохраняет только `*.automaticDestinations-ms` и `*.customDestinations-ms`.
Отдельные LNK из корня Recent и ветки RecentDocs/ComDlg32 больше не собираются.
Имя raw-источника `recent_files` сохранено для совместимости; прежние коллекции не удаляются.
Декодирование выполняется вручную через JLECmd. Готовые CSV поместите в
`<проект>/recent/` или подкаталог (например, `recent/procede_recent/`), затем
пересканируйте проекты. JLECmd автоматически не запускается.

В общей сводке «Профиль пользователя и узла» появляется профиль по Jump Lists:
приложения, типы документов, сетевые пути и возможные сценарии работы с основаниями.
Владелец определяется по совпадению `SourceFile` с артефактом коллекции, не по пути
целевого документа. При отсутствии однозначного совпадения профиль не приписывается
учётке сбора. Сохраняйте имена выгруженных файлов при ручной обработке.

`AppIdDescription` из CSV имеет приоритет; резервный словарь AppID проверен по
[справочнику JumpList](https://github.com/EricZimmerman/JumpList/blob/master/JumpList/Resources/AppIDs.txt).
Неизвестные AppID не угадываются. Ссылка на EXE не доказывает запуск, CustomDestinations
могут содержать статические задачи. Счётчики не суммируются как число запусков,
времена целевого файла не выдаются за время действия пользователя. Повторные экспорты
не увеличивают статистику профиля; исходные CSV-строки доступны в деталях.

### Проверка доменных ACL

ACL импортируются после остальных источников, с разрешением SID в имена.
В представлении ACL доступны фильтры интересующих разрешений, совпадений
с текущим токеном и всех ACE (включая штатные, Deny и наследуемые).
Отбор эвристический: это приоритет проверки, а не подтверждение эффективного доступа.
Смена пароля не приравнивается к сбросу; профильные права встроенных ролей
отделяются от нестандартных разрешений. Основа стандартных шаблонов:
[Microsoft AD schema](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adsc/2d27d2b1-8820-475b-85fd-c528b6e12a5d)
и [SID встроенных ролей](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/understand-security-identifiers).
Все исходные ACE остаются доступны. Совпадение с токеном не учитывает полный
порядок Allow/Deny, условные ACE или применимость права к объекту.
Импорт проекта атомарный: ошибка не оставляет половину нового индекса,
предыдущий индекс сохраняется, ошибка отображается после пересканирования.

Из корня `as3rch_portable`:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m analyzer_web.server
```

Интерфейс доступен на `http://127.0.0.1:8765`.

Явные параметры:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m analyzer_web.server --collections /path/to/from_portable/new --database /path/to/analyzer.db --host 127.0.0.1 --port 8765
```

Внешние Python/Node-зависимости не требуются. Индекс SQLite создаётся в
`analyzer_web/state/analyzer.db`; raw-коллекции не изменяются.

## Реализовано

- проекты по каталогам;
- импорт index schema 3.0 и raw schema 2.0;
- русский интерфейс с разделами по происхождению: контекст, логи, сеть, домен,
  конфигурации, права, браузеры и Recent;
- список источников, диагностика, постраничные сырые записи и сохранённые файлы;
- декодированные UserAssist, браузеры и AD внутри соответствующего источника,
  переключение на исходные данные и фильтр читаемых записей;
- наблюдения с основаниями внутри разделов;
- опциональные графы по кнопке: выбор объекта и 12/18/24 узлов максимум,
  подписанные стрелки, таблица связей, переход к записи-основанию;
- точный поиск по проиндексированным JSON;
- UserAssist ROT13 и структура Windows 7+;
- Chromium/Firefox History, downloads, bookmarks и extensions;
- AD SID/GUID/FILETIME/UAC/groupType normalization;
- Recent/Jump Lists из CSV-экспортов, UserAssist, браузеры, AD и AD ACL.

## Правила интерпретации

Сводка разделяет конфигурационные находки, контекст доступа, профильные
наблюдения и ограничения сбора. Приоритет определяет порядок ручной проверки;
он не подтверждает эксплуатацию или компрометацию.

- События установки служб и задания планировщика описывают ПО и автоматизацию.
  Путь в профиле, сценарий, интерпретатор или SYSTEM сами по себе не повышают риск.
- UserAssist, браузеры, Recent CSV и история PowerShell образуют отдельные
  статистические срезы по профилям. Неизвестный профиль явно обозначается.
  Служебные записи UEME исключаются из рейтинга приложений.
- Recent размечается по типу файла и сетевому пути. Поиск по списку названий
  offensive-инструментов удалён. Сырые LNK/JumpLists по-прежнему не декодируются.
- DNS-кэш относится к узлу; по нему нельзя однозначно определить пользователя.
  Номер слушающего порта даёт предположение о протоколе, требующее подтверждения.
- AD: SPN, пути профилей и сценариев — сведения; настройки предаутентификации,
  делегирования и шифрования — основания проверки. Повторные объекты
  дедуплицируются; отключённые учётки и штатное делегирование DC не получают
  автоматический высокий приоритет. PASSWD_NOTREQD не доказывает пустой пароль.
- SMB: отсутствующее поле означает «нет данных». Разрешающая ACE на запись
  широкой группе требует сопоставления с NTFS и Deny; итоговый доступ не вычисляется.
- Основания находок сохраняют категорию `finding_type` и наблюдаемые данные.

После изменения правил перезапустите сервер с обычной начальной индексацией
или нажмите «Обновить коллекции», чтобы пересчитать старые находки.

## Ограничения

- приложение предназначено для локального запуска и не содержит аутентификации;
- не публикуйте его на внешнем интерфейсе без reverse proxy и контроля доступа;
- LNK, Jump Lists, RecentDocs и Shell Items не декодируются;
- UserAssist других форматов остаётся с `decode_status=unsupported`;
- браузерные SQLite обрабатываются из временной копии, но живой снимок коллектора
  мог быть несогласованным;
- эффективные ACL конкретной учётки не вычисляются;
- AD-граф использует только явные member/memberOf, servicePrincipalName и
  msDS-AllowedToDelegateTo. При отсутствии атрибутов граф остаётся пустым;
- граф сети связывает TCP-слушателей и UDP-привязки с процессами по PID.
  Службы связываются по ProcessId, если поле присутствует. Без PID совпадение
  пути EXE работающей службы помечается пунктиром как неподтверждённое;
  общие svchost.exe/dllhost.exe так не сопоставляются;
- граф логов связывает службу с учётной записью запуска и XML-событием
  установки по имени службы; совпадения неоднозначных DisplayName пропускаются;
- граф токена показывает группы и привилегии вместе с исходными состояниями;
- показываются непосредственные соседи выбранного объекта. Число скрытых
  связей указано явно; единый граф проекта доступен отдельно и из модульных разделов;
- имена технических полей в деталях и исходные значения не переводятся.
